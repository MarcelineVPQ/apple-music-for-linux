| Relaunch after an update: no window, no tray | **Done** | 0.15.36-dev.1. 0.15.34 → 0.15.35-dev.1 on 2026-10-16: the relaunched copy ran with no window or tray, and a second launch did nothing. Cause: the relaunch passed Sonata's own PATH on, which AppRun starts with the AppImage's FUSE mount; each relaunched copy inherited every earlier copy's mount. The relaunch unit (systemd-run, ExitType=main) killed the old copy's FUSE helper with its mount still in place, so the mount answered ENOTCONN, `execFile('gdbus')` in readDesktopScheme threw, and the throw stopped startup before createWindow/createTray. Fix: relaunch.js (env without AppImage mounts, `-p ExitType=cgroup` like KDE's launcher, retry without it for systemd < 250, the old flags carried, no --hidden); other AppImages' mounts dropped from PATH/LD_LIBRARY_PATH at start (covers a relaunch by 0.15.34/0.15.35-dev.1 code); the gdbus spawns fail soft (logged once); every startup step before the window guarded; a second launch makes the window if there is none. Checked end to end on an isolated copy (loopback signed test feed, Restart now, a dead FUSE mount on PATH): the old build reproduces the journal's trace, the fixed build shows its window. |
